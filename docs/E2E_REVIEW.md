# E2E 测试复盘（用户视角）

> 日期：2026-10-31　基于本次真实运行记录与实测复查，不凭印象。
> 结论：**管道工程上跑通了，但研究质量上有 5 个真问题**。
> 其中 3 个会直接导致"挖出来的因子不可信"，必须修。

---

## 用户视角的实际体验

输入「ETF截面动量因子」，我期待看到：截面动量相关的论文 → 动量类因子 → 在我的 ETF 池上的回测。

实际得到的：

| 环节 | 实际发生 | 是否符合预期 |
|---|---|---|
| 论文召回 | Top1 = *ChatGPT in Systematic Investing* | ❌ 跑偏 |
| 因子提取 | `spy_drawdown_depth` / `vix_stress_relief` / `llm_news_momentum_score` | ❌ 数据不存在 |
| 回测 | 全部 FAIL_IS | ⚠️ 结论对，但原因不对 |
| 耗时 | 4 因子约 10 分钟 | ❌ 太慢 |
| 成本 | $0.15/次 | ✅ 可接受 |

**最伤的一点**：系统给出了"0/4 通过双层门控"这个看起来很专业的结论，
但实际上这 4 个因子**压根不该被测**——它们要的数据我没有。
用户会误以为"我的数据上动量因子无效"，而真相是"系统测了错的东西"。

## P-1　论文召回跑偏：时间权重压倒相关性 🔴

### 实测证据

```
最终排序（输入「ETF截面动量因子」）：
  1. [rel=7] 2025-10-30  ChatGPT in Systematic Investing        ← Top1
  2. [rel=8] 2023-02-21  Transfer Ranking: Cross-Sectional Momentum
  3. [rel=8] 2023-02-20  Spatio-Temporal Momentum: ... Cross-Sectional
  6. [rel=8] 2020-12-13  Building Cross-Sectional Systematic Strategies
```

三篇 rel=8 的**真·截面动量**论文，全部排在 rel=7 的 ChatGPT 论文之后。

### 根因（可算出来）

`paper_search_agent._combined_sort`：`combined = 0.6×rel/10 + 0.4×date_norm`

```
论文                                 rel   rel项    时间项   combined
ChatGPT in Systematic Investing       7   0.420   0.367    0.787   ← 赢
Transfer Ranking: Cross-Sect Momentum 8   0.480   0.165    0.645
Building Cross-Sect Strategies        8   0.480   0.000    0.480
```

**0.4 的时间权重足以推翻 1 分的相关性差距。** 时间跨度 2020→2026 被归一化到
满量程，等于让"新"这件事获得了与"相关"同等的话语权。

### 修法

1. 时间权重从 0.4 降到 **0.15**，或改成只在相关性同分时做 tie-break
2. `rel ≤ 6` 直接淘汰（当前 `min_score=5` 太松）
3. 时间归一化改用**半衰期衰减**（如 3 年半衰），而非线性满量程归一化

## P-2　因子要的数据根本不存在 🔴

### 实测证据

数据池实际内容（117 个**中国 ETF**）：
```
510300_沪深300ETF  511010_国债ETF  508000_华安张江REIT  501018_南方原油 ...
```

LLM 生成的因子要什么：
```
spy_drawdown_depth          → SPY（美股）
vix_stress_relief           → VIX（美股恐慌指数）
qqq_dia_relative_momentum   → QQQ / DIA（美股）
llm_news_momentum_score     → 新闻数据
rate_relief_signal          → 利率数据
```

**全都没有。**

### 更隐蔽的问题：LLM 做了静默代理

`vix_stress_relief` 的代码注释：
> *"Since we don't have VIX directly, we compute a market-level VIX proxy:
> cross-sectional average of rolling realized vol"*

它自己找了替代品，**但没告诉任何人**，而且：
```python
vix_threshold = 25.0   # 为美股 VIX 校准的阈值
```
把美股 VIX 的 25 这个数字，直接套在中国 ETF 的已实现波动率上 —— 毫无依据。
这解释了它为什么单调性 **-0.90**（完全反向）。

用户看到的是"这个因子 FAIL 了"，看不到"它测的其实是个瞎编的代理变量"。

### 修法

1. **提取阶段就把可用数据告诉 LLM**：当前 `factor_extract_agent` 只看论文摘要，
   完全不知道有什么数据。必须把标的清单+字段+市场（中国/美国）注入 prompt。
2. **加数据可用性前置校验**：spec 的 `data_requirements.fields` 与实际数据对不上
   → 直接跳过，标记 `SKIP_NO_DATA`，不浪费代码生成与回测。
3. **禁止静默代理**：prompt 明确要求"数据缺失就报错退出，不要自行替代"。
   代理变量必须是用户知情的选择，不是 LLM 的自由裁量。

## P-3　截面不可比：波动率极差 200 倍 🔴

### 实测证据

池子构成：
```
股票类 ETF   98
REITs        9
国债         3
其他债券     2
黄金         2
原油         2
商品         1
```

实测年化波动：**最低 0.2%，中位 24.7%，最高 39.8% —— 极差 200 倍**。

### 为什么这是问题

把国债ETF（波动 0.2%）和股票ETF（波动 25%）放进同一个截面做动量排序，
排序结果会被**资产类别**主导，而不是动量强弱：债券永远在一头，股票永远在另一头。

这使"分层单调性"这个我最依赖的指标**失去意义** —— 它测出来的单调性可能只是
"资产类别的波动率阶梯"，不是因子的预测能力。

### 修法

1. **按资产类别分池**：股票类/债券类/商品类分别做截面，或只用股票类 98 只
2. 或者**波动率标准化**后再排序（factor / rolling_vol）
3. 最低成本的做法：加一个 `universe_filter` 参数，默认只用股票类 ETF

## P-4　"FAIL_IS" 的信息量不足 🟡

当前用户看到：
```
[FAIL_IS] vix_stress_relief
  → |t|=0.98 < 2.13; 单调性=-0.900 < 0.6; 多空Sharpe=-0.501 < 0.5
```

看起来很专业，但用户无法判断这是**因子不行**还是**系统没测对**。
实际上这个因子的失败原因是"VIX 数据不存在 + 阈值瞎编"，而门控报告完全没提这件事。

### 修法

失败要分层归因：
```
SKIP_NO_DATA     数据不存在 → 压根没测（当前缺失）
FAIL_SHAPE       因子形状不可用（已有：稀疏/截面退化）
FAIL_IS          真的测了，指标不达标
FAIL_OOS         IS 过了，OOS 掉了
```
用户最需要区分的是第一类和第三类。

## P-5　串行太慢 🟡

实测全自动模式 4 个因子约 **10 分钟**（13:38→13:47 推进 2 个）。
每个因子串行走「LLM 生成 → 沙箱执行 → 双层回测」。

因子之间完全独立，沙箱和回测都是 CPU 密集 → 并发 3 个可压到约 1/3。

## 做对了的部分（避免过度自我批评）

这些经实测确认有效，不需要动：

- **双层门控确实在筛东西**：`rate_relief_signal` 单调性 +1.00、扣费后多空 Sharpe
  0.46，只因 t=1.42 < 1.64 和换手 0.338 > 0.3 被拦 —— 这是合理的判断
- **D4 修复有效**：mom_60d vs mom_120d 净值相关 0.806（旧方法 0.025 漏判）
- **防泄漏有效**：泄漏因子被抓出 Sharpe>3、单调性>0.9；随机因子无边际
- **代码生成修复有效**：0% → 100% 一次成功率
- **成本可控**：$0.15/次，且 `_SCORE_LIMIT` 实测省 52%

## 修复优先级

```
🔴 必修（否则结论不可信）
  P-2  数据可用性校验 + 把可用数据注入提取 prompt + 禁止静默代理
  P-3  按资产类别分池（或只用股票类 98 只）
```

## 附录 B：修复后复测（2026-10-31）

### 修复生效情况

| 问题 | 修复前 | 修复后 |
|---|---|---|
| P-1 Top1 论文 | *ChatGPT in Systematic Investing* (rel=7) | *Transfer Ranking: **Cross-Sectional Momentum*** (rel=8) |
| P-2 生成的因子 | `vix_stress_relief` / `spy_drawdown_depth` / `llm_news_momentum_score` | `cross_sectional_momentum` / `time_series_momentum` / `volume_adjusted_momentum` |
| P-3 截面池 | 117 只，波动极差 200× | **92 只，极差 2.2×** |
| P-4 失败归因 | 只有 FAIL_IS | 新增 `SKIP_NO_DATA`，UI 区分「未测」 |

### 复测中新发现的问题（已修）

**换手门槛是频率的函数，不是因子质量的函数。**
实测同一因子 `mom_60d`：日频换手 0.415 / 周频 0.188 / 月频 0.091。
固定 0.30 使日频因子永远不达标、月频轻松通过。

上一轮 E2E 四个因子换手全挤在 0.32–0.33，**全部因换手被拦**，
掩盖了信号本身的表现。改为按频率校准后：

```
因换手被拦的因子: 4/4 → 0/4
失败归因全部落到 t 值 / 单调性 / 多空 Sharpe
```

另修：空输入被接受（现 422）、PASS 因子入库前未复查数据可用性
（库里曾有一条 `llm_news_momentum_score` 污染去重基线，已删）。

### 查了但不是问题的

**符号翻转后 Sharpe 不镜像**（-0.591 vs +0.438）。零成本下仍不对称，
但日均收益精确镜像。根因是几何年化的数学性质：
`+0.4%/日 → +173%` 而 `-0.4%/日 → -64%`。正确的金融口径，非 bug。
测试只对算术口径指标断言镜像。

## 附录 C：新门控的实际价值（最有力的证据）

用同一批朴素动量因子，对比旧门控（`mine_momentum.py` 的 ETF 门槛：
`IC>0.02 / icir_daily>0.06 / cov>0.60`）与新双层门控：

```
因子            IC       icir_d   cov  | 旧判定 | 单调性   多空Sharpe  新判定
mom_20d       +0.0118   0.034   100%  |  FAIL  | +0.80    +0.197     FAIL_IS
mom_60d       +0.0123   0.034   100%  |  FAIL  | -0.40    -0.591     FAIL_IS
mom_120d      +0.0129   0.035   100%  |  FAIL  | +0.00    -0.503     FAIL_IS
mom_250d      +0.0389   0.105   100%  |  PASS  | +0.90    +0.117     FAIL_IS

旧门控通过 1/4    新门控通过 0/4
```

**`mom_250d` 是关键案例**：IC 0.0389、icir_daily 0.105、覆盖率 100%，
旧门控判 PASS。新门控看到它多空 Sharpe 只有 0.117 —— 排序方向对、
信号稳定，但**赚不到钱**，于是拒绝。

更极端的例子是 `mom_60d` 的分层收益：
```
Q1 +5.4%  Q2 +2.6%  Q3 -2.3%  Q4 +7.5%  Q5 -6.3%
```
IC 为正（+0.0123）、月胜率 66%，但**最高分位 Q5 是最差的**。
收益集中在中间层，多空组合（Q5−Q1）恰好错过赚钱的层。

这不是 bug —— IC 是秩相关，不含收益幅度信息，与分层收益脱节是已知现象。
但它恰好说明为什么必须补回测层：

> **IC 显著 ≠ 能赚钱。** 只看 IC/ICIR 的系统会把这类因子判为有效。
