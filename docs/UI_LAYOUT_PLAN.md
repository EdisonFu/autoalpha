# 界面布局优化建议

> 基于实测，不是凭感觉。测量环境：1340×900 视口，演示模式（3 篇论文 / 2 个假设 / 3 个因子）。

## 问题有多大

```
初始          1024px   1.1 屏
演示结束      5065px   5.6 屏      增长 4.9×
```

而演示只有 3 个因子。按单卡高度外推到真实规模：

| 内容 | 单项高度 | 10 项 |
|---|---|---|
| 因子结果卡 | 639px | **6390px ≈ 7.1 屏** |
| 论文卡 | 206px | 2060px ≈ 2.3 屏 |

各面板占比（当前 3862px 面板总高）：

| 面板 | 高度 | 占比 |
|---|---|---|
| **回测结果** | **2026px** | **52%** |
| 选择论文 | 767px | 19% |
| 因子假设 | 454px | 11% |
| 研究意图 | 389px | 10% |
| 数据准备 | 226px | 5% |

---

## 结论：折叠必要，但不够

你的想法（完成即折叠）能解决上游面板的堆积 —— 意图、论文、假设、数据加起来 1836px，
折叠后约 200px，**省下约 1.6 屏**。

但**回测结果独占 52%，而它恰恰是不该折叠的那个** —— 它是用户真正要读的东西。
10 个因子时它自己就 7 屏。所以：

> 折叠解决「历史步骤占地方」，不解决「当前结果本身太长」。
> 两个问题得分开治。

---

## 建议（按性价比排序）

### 🔴 A. 上游面板完成即折叠（你的思路，直接做）

完成的阶段收成一行摘要，点击展开：

```
✓ Step 1 · 研究意图    A股 · 动量 · 日频 · 置信度 86%              ⌄
✓ Step 2 · 选择论文    已选 1 篇：Transfer Ranking in Finance…     ⌄
✓ Step 3 · 数据准备    92 标的 · IS 752d / OOS 231d · 门槛 0.0114  ⌄
✓ Step 4 · 因子假设    2 个 · etf_cross_sectional_momentum 等       ⌄
```

**要点**：摘要行必须带关键信息。折叠成「✓ 已完成」等于让用户必须展开才知道发生了什么，
反而更费事。

- 省约 **1.6 屏**
- 自动折叠上一阶段，但**不自动折叠当前阶段**
- 折叠状态记在内存即可，不必持久化

### 🔴 B. 因子结果改紧凑列表 + 详情展开（收益最大）

当前每个因子一张 639px 大卡，含 IS/OOS 双栏 + 净值图 + 分层柱。
改成一行摘要，点开才看详情：

```
状态  因子名                            t     单调   多空   换手   
✓    etf_cross_sectional_momentum    3.42  +0.90  0.81  0.11   ⌄
✗    etf_reversal_overlay            2.10  -0.30 -0.12  0.19   ⌄   ← IC显著但分层反向
✗    etf_volume_weighted_momentum    1.58  +0.60  0.37  0.31   ⌄
```

- 单行约 **44px**，10 个因子 440px（**从 7.1 屏降到 0.5 屏**）
- 一屏能横向对比所有因子 —— 这比逐个滚动看更有用
- PASS 的默认展开（那是结果），FAIL 的默认收起（那是诊断）
- 失败原因在行内用一句短语提示，不必展开就知道为什么没过

### 🟡 C. 右侧固定摘要栏

宽屏（≥1200px）时左侧流程、右侧常驻一栏：当前阶段、通过数、token 花费、关键指标。
窄屏回落为单列。好处是滚到页面任何位置都知道全局状态。

### 🟡 D. 步骤条可点击跳转

已完成的步骤点一下滚动到对应面板。配合折叠，步骤条就成了导航。

### 🟢 E. 日志默认收起

210px，且多数时候不需要看。收成一行「运行日志 (23 条) ⌄」。

### 🟢 F. 论文列表默认只显示前 5 篇

「显示全部 12 篇」按钮展开。10 篇论文 2060px 里，多数用户只看前几篇。

---

## 不建议做的

**分页 / Tab 切换阶段。** 流水线的价值之一是能回看「从哪篇论文推出了这个因子」，
切成 Tab 会切断这条线索。折叠保留了上下文，Tab 丢掉了。

**虚拟滚动。** 因子数量级是 10 不是 1000，复杂度不划算。

**自动滚动到最新面板。** 用户可能正在读上面的内容，被拽走很烦。
更好的做法是在视口外出现新结果时，底部弹一个「↓ 新结果」提示，点击才跳。

---

## 实施顺序

```
1. B（因子结果紧凑列表）   收益最大：7.1 屏 → 0.5 屏
2. A（上游面板折叠）       你的思路，省 1.6 屏
3. E + F（日志/论文收起）  便宜，各省几百 px
4. D（步骤条跳转）         折叠后才有意义
5. C（固定摘要栏）         锦上添花
```

B 和 A 做完，10 因子场景从约 **13 屏降到约 3 屏**。
